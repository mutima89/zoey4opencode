Part 1: Install

Prerequisites

Before installing Zoey4OpenCode, make sure you have:

  • OpenCode installed and working
  • Bun (JavaScript runtime) — version 1.0 or higher
  • Internet connection (for the initial setup only)
Already have everything? The installation is fully automated. If not, get OpenCode from opencode.ai and Bun from bun.sh.

Installation Steps

1
Check Bun is installed

Open a terminal and run: bun --version
You should see a version number like 1.3.14.

2
Install plugin dependencies

Run: bun install inside the plugin folder:

cd ~/.config/opencode/plugins/zoey4opencode bun install
3
Build the plugin

Run: bun run build (or bun build ./src/index.ts --outdir ./dist --target bun --format esm)

cd ~/.config/opencode/plugins/zoey4opencode bun run build
4
Register in OpenCode config

Add the plugin path to ~/.config/opencode/opencode.json:

{ "plugin": [ "...other plugins...", "C:\\Users\\YOUR_USER\\.config\\opencode\\plugins\\zoey4opencode\\dist\\index.js" ] }

Companion agents are auto-discovered from ~/.config/opencode/agent/companions/.

5
Restart OpenCode

Close and reopen OpenCode. The plugin loads automatically on startup.

That's it! Five steps and you're done. The whole process takes about 2 minutes.

Verifying It Works

After restarting OpenCode, try these checks:

  • Type /companion list — you should see 4 companions listed
  • Type @Atlas Hello! Can you help me? — Atlas should respond
  • Type /memory stats — you should see memory statistics (even if zero)
Nothing showing up? Check that:
  • The plugin path in opencode.json uses double backslashes (\\)
  • The dist/index.js file exists and is not empty
  • You restarted OpenCode after making config changes
Part 2: Interact

Talking to Companions

There are three ways to interact with your Zoey companions:

Method 1: @Mention (Recommended)

Simply type @ followed by the companion's name anywhere in your message:

@Atlas What are the best practices for REST API design? @Architect Design a folder structure for a web application @Operator How do I set up Docker for this project? @Mentor Review my error handling code

Method 2: Slash Commands

Use /companion to manage companions and /memory for memory operations:

/companion list — Show all companions /companion switch Atlas — Switch to Atlas /companion status — Check active companion /companion configure Mentor "Focus on security" /memory save "decision text" tags=tag1,tag2 /memory recall "search keywords" /memory list limit=10 /memory stats

Method 3: Use Tools Directly

Advanced users can call the underlying tools. These are the same tools companions use internally:

zoey.memory.save({ content: "...", tags: ["decision"] }) zoey.memory.recall({ query: "database decision" }) zoey.companion.switch({ name: "Atlas" }) zoey.companion.list({})

Using Memory

The memory system is what makes Zoey4OpenCode different from regular AI tools. It remembers things across sessions so you don't have to repeat yourself.

What to Save in Memory

TypeExampleTags
Decisions"We chose PostgreSQL for the database"decision database
Patterns"Use repository pattern for data access"pattern architecture
Config"API endpoint: https://api.example.com/v2"config
Bugs"Bug #42: null pointer in login handler — fixed by adding null check"bug fixed
Lessons"Always validate input before database queries"lesson security

Memory Tips

  • Save immediately — right after making a decision, save it
  • Use consistent tags — stick to tags like decision, pattern, config, bug
  • Be specific — "Use SQLite for local storage" is better than "database stuff"
  • Search before asking — check memory first before re-asking a question
  • Clean up — remove outdated or incorrect memories with /memory forget [id]

Example Workflows

Workflow: Research a New Technology

  1. @Atlas Research the differences between SQLite and PostgreSQL for desktop apps
  2. Review Atlas's findings
  3. /memory save "Use SQLite for local-first, PostgreSQL for cloud sync" tags=decision,database
  4. @Architect Design the database layer based on this decision

Workflow: Code Review Session

  1. @Mentor Review src/auth/login.ts for security issues
  2. Apply Mentor's suggestions
  3. /memory save "Login module reviewed — added rate limiting and input validation" tags=review,security

Workflow: Project Setup

  1. @Architect Plan the project structure for a task management app
  2. @Operator Set up the development environment with Docker
  3. /memory save "Project structure: frontend/ backend/ shared/ — Docker Compose for dev" tags=architecture,config
Part 3: Adjust

Configuring Companions

You can customize how each companion behaves by giving them custom instructions.

Add Custom Instructions

/companion configure Mentor "Always review code for security vulnerabilities first. Focus on OWASP Top 10. Be thorough but kind in your feedback."

View Current Instructions

/companion configure Mentor

This shows the current custom instructions (if any) for that companion.

Companion Temperatures

Each companion has a "temperature" setting that controls how creative or focused they are:

CompanionTemperatureStyle
Atlas0.3Balanced research — thorough but focused
Architect0.2Precise and structured — less creative, more reliable
Operator0.1Very deterministic — exact commands, no creativity
Mentor0.3Balanced teaching — clear explanations with examples

Temperatures range from 0.0 (very focused, predictable) to 1.0 (very creative, unpredictable). These are set in the agent definition files and can be adjusted there.

Customizing the Skill

The Zoey Companions skill auto-loads when you mention companion-related keywords. The skill file is at:

~/.config/opencode/skills/zoey-companions/SKILL.md

You can edit this file to:

  • Add new triggers — add keywords that activate the skill
  • Update workflows — change the example workflows shown
  • Add tips — include your own usage tips and best practices
Format: The SKILL.md file uses frontmatter with triggers section. Each trigger has a keyword and a description. When you type those keywords, the skill content is loaded into the agent's context.

Managing Your Data

Where Data Is Stored

All data is stored locally on your machine at:

~/.config/opencode/plugins/zoey4opencode/store/

FileContains
zoey-memory.dbAll memory entries (content, tags, context, agent, timestamps)
zoey-companions.dbCompanion state, usage stats, custom instructions

Backing Up

To back up your memories and companion data, simply copy these two files to a safe location.

Resetting

  • Delete individual memories: /memory forget [id]
  • Clear all memories: Delete zoey-memory.db while OpenCode is closed
  • Reset companion stats: Delete zoey-companions.db while OpenCode is closed
  • Full factory reset: Delete the entire store/ folder — databases will be recreated fresh
Warning: Deleting database files is permanent. Make a backup first if you want to keep your data.

Privacy Guarantee

All data stays on your computer. The SQLite databases are local files. No data is ever sent to any external server, API, or cloud service. Your memories, companion configurations, and usage patterns are yours alone.

Troubleshooting

Plugin not loading

  • Check that ~/.config/opencode/opencode.json has the correct path to dist/index.js
  • Make sure the path uses double backslashes (\\) on Windows
  • Verify the file exists: dist/index.js should be about 465KB
  • Rebuild the plugin: bun run build in the plugin directory

"Command not found" for /companion or /memory

  • Make sure the command files exist in ~/.config/opencode/commands/
  • Check the filenames: companion.md and memory.md
  • Restart OpenCode after adding/modifying commands

Companion agents not showing up in @ mentions

  • Verify the agent files exist in ~/.config/opencode/agent/companions/
  • Each file must have frontmatter with mode: subagent
  • Agent names in the frontmatter must match (Atlas, Architect, Operator, Mentor)

Memory operations failing

  • Check that the store/ directory exists and is writable
  • Verify the SQLite databases are not corrupted (check file sizes)
  • Try deleting the database files and letting them recreate

Still having issues?

Check the build output for errors: run bun run build in the plugin directory. The error messages will tell you what's wrong. Common issues include:

  • Missing node_modules — run bun install
  • TypeScript errors in source files
  • File permission issues on the store directory
